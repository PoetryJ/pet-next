六、隔离 helper：scripts/test-run-context.mjs
------------------------------------------------
API（与冻结口径一致）：
  createRunContext({ label, kind, appRoot? }) ->
    { dir, logDir, configPath, modelLogPath, sshLogPath, freePort(), env(extra), snapshot(), cleanup() }
  startOwnXvfb({ label }) -> { display, socket, pid, stop() }
语义要点：
- 唯一：<tmp>/pet-next-runs/<kind>/<时间戳>-<label>-<pid>-<随机>/；logs、userData、config 均在本轮目录内；
  configPath 可直接给 PET_NEXT_REMOTE_CONFIG，modelLogPath→FAKE_MODEL_LOG，sshLogPath→FAKE_SSH_LOG。
- 端口：freePort() 只从内核取一次临时端口并登记，snapshot().ports 可核对；不预占共享端口。
- 显示器：startOwnXvfb 从 :120 起认领（跳过 :94、:95-:97），靠 /tmp/pet-next-xvfb-<n>.lock 排他，
  stop() 只按自己的 pid 发 SIGTERM→SIGKILL，不按名字批量杀，不影响别人的 Xvfb/Electron。
- 清理：cleanup() 先探测本轮端口是否仍被监听、记录日志/配置残留，写 <logDir>/residual.json 并返回
  { ok, ports:{allocated,stillListening}, files, notes, dirKept }；ok=false 默认保留目录当证据，
  只删本轮目录，不杀任何外部进程。
- 构建先完成再启动：helper 不构建；顺序是 createRunContext（只建目录）→ 等构建产物 →
  startOwnXvfb → spawn(env: ctx.env({ DISPLAY: xvfb.display }))。见模块头注释。
单测（8 例，含 Xvfb 两路互不影响、cleanup 先断言后删、无关进程存活）：
  node --experimental-strip-types --test --test-reporter spec scripts/test-run-context.test.mjs
  结果：tests 8 / pass 8 / fail 0 / skipped 0 / duration_ms 315.858457 / exit 0
  原始输出：helper/spec.stdout.log、helper/spec.stderr.log、helper/exit.txt、helper/environment.txt
  跑完检查：/tmp/pet-next-xvfb-*.lock 0 个，无本 helper 起的 Xvfb 残留。
