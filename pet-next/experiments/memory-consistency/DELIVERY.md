# 记忆一致性实验 · 一页结论（M3-13 R0）

**问题.** 桌宠的长期记忆里，「生成成功」「软件呈现」「用户确认」「工具完成」容易被互相冒充；
「单次请求取消」容易被当成「长期任务撤销」；后台整理可能用旧视图覆盖新状态。产品当前没有呈现 ack 通道，
也没有可回放的记忆证据链。

**经典对应.** 事件溯源 + 单写者提交 + 读模型（CQRS）；笔记作为物化视图，用依赖版本判定是否过期；
崩溃恢复走「追加日志 + 版本化快照 + 清单原子切换」。

**本轮变化.** 把上述性质做成可跑、可判分、可复现的离线实验：冻结契约 v1，建 24 对（48 条）开发轨迹与
8 对（16 条）新模板轨迹，独立写期望并配六种错误实现做负控，另加磁盘日志/快照恢复、崩溃注入、
四策略预算、产品纯模块回放、固定规模成本比较与离线证据时间线。

## 有效结果（全部为机制层，不是模型能力）

| 门 | 结果 | 证据 |
| --- | --- | --- |
| G1 | 通过 | 48 轨迹 / 24 对 / 143 断言全绿；6/6 负控被指定反例检出；`fetch` 哨兵 0 调用 + 静态扫描 0 命中 |
| G2a | 通过 | 存储 12 项 + 恢复 7 项；8 个崩溃点里 7 个已注入验证（快照前后各一），已确认事件与补丁 100% 恢复 |
| G2b | 通过（限定） | 全量/局部重建在 16×500 事件、100/1000/10000 规模上有效事实集合一致；反例「漏变更集」能被等价门抓到 |
| P1 | 通过 | 16 条新模板 47 断言全绿；防泄漏 152 次采样 0 发现；24 对反事实行为不同且不变量成立；重放等价 |
| P2 | 通过（条件项） | 10k 事件下局部扫描 ~50 事件 vs 全量 ~9574；平台 5 项 pass + 1 项 not_proven；未来 runner dry-run 528 次调用、341,760/400,000 字符预算，零重试 |

测试合计 132 项，11 个套件；`run.mjs --all` 一次跑完约 20 秒（含成本研究）。

## 失败与处理

- 平台：单核 2.2GB、默认 PATH 无 `node`。装 Node 后在同一独立工作树顺序执行四个工作流，未并行抢占。
- 评分器早期把 `sessionId` 写死成开发集值，新模板全部读成 `absent`：改为从轨迹读取后一次修好。
- A3 对的两条变体语义方向与初版期望相反：以契约文字为准改期望，并保留「期望先于实现」的顺序说明。
- root 下 `chmod` 测不出无写权限路径：该项标 `not_proven`，不写成通过。
- M3-12 R1 遗留：从同一份原始采样独立重算 CPU 秒/分钟，与 `perArm` 逐值完全一致（0 偏差），
  故判定「原任务已完成、复用不重做」，只写重算结果与接续说明，未改原工作树。

## 未证明（一律 not-run，不得读成通过）

真实模型生成质量与长程语义记忆；用户是否读到；断电/文件系统永久损坏下的耐久性；
高依赖扇出下的成本；Windows 实跑；演示页的真实浏览器点击交互；任何产品采用结论。

## 建议

**通过离线机制验收，但不要据此接产品。** 下一步先把 `future-run` 的 dry-run 计划交给 owner 定模型与预算，
做一次受控的小规模 live 实验；在拿到真实呈现 ack 通道之前，任何「用户已看到/已记住」的说法都只能是 unknown。
