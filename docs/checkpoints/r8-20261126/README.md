# PetNext 持续委托实验 · 暂停交接

项目于 2026-11-26 暂停。它验证桌宠能否长期跟进一项委托，记住用户何时希望被打断，理解改口，在真正可以执行时提供选择，并留下能独立核验的产物。当前成果是可复跑的工程原型和真实模型实验。

R8 以 `0b38ccf` 为基线。产品实验代码冻结于 `1f5d903`，运行与评分入口冻结于 `9c25529`，Vibe 的交付报告提交为 `4fff1f1`。源码位于 `pet-next/experiments/task-followup/`。R0–R3.1 的离线记忆机制位于 `pet-next/experiments/memory-consistency/`。[恢复手册](RESUME.md) · [实验环境](ENVIRONMENT.md) · [原始证据](ARCHIVE.md) · [阶段索引](HISTORY.md)

## 当前能演示的两件事

1. **第一份 CI 失败时，可以选择先分析这份。** 在 G1-F 的 V-C 和 T-C 真跑里，问题同时说明哪份失败、哪份还在等，并提供先分析、等另一份和跳过。本次先分析的授权只覆盖失败报告的版本和文件 SHA。之后另一份报告到达，没有再次提问。结果是可核验的单来源分析。
2. **一轮成功时保持安静，下一轮失败时继续提醒。** G3-C 三臂在第二轮都产出完整分析，输入为 A 的第二版与 B 的第一版。按原始送达时间，V-C 和 T-C 实现了第一轮安静、第二轮失败后单次询问。V-R 在第二轮失败落盘前多发一条主提醒，所以严格口径是 2/3。显式结束的配对 G3-E 只有 V-C 安静归档，另两臂仍问。

R7 的独立复跑也保留了明确差分。同为 A 成功、B 失败，换一条早期承诺，T-C 分别提问后生成分析、或静默归档。两个最终动作都由已编译的条件直接决定。这个结果依赖的是受控 CI 工作流里的两条承诺。对未见措辞和真实使用环境的适用性仍待评估。

## R8 结果与限制

以下数字来自 R8 交付的 `score/score.json`、`verify.json` 与 `R8-REPORT.md`。其中 V-R 为版本记忆＋规则，V-C 为版本记忆＋条件，T-C 为文本摘要＋条件。条件策略发生回退时，以逐次决策记录为准。

- **原评分通过 11/24。** V-R 1/8，V-C 6/8，T-C 4/8。保留原口径以便重算。G4 两组实际收到相同的更正语句「A 成功再来问我」，AS 的预期却是在 A 成功时归档，因此 G4 无法用来确认改口方向的能力。恢复时先对齐实际送出的语句与预期，再重跑改口。
- **可核验分析**有 3 份局部分析与 10 份全量分析。产物数量和正确运行数量口径不同。
- **仍有摩擦。** 12 个应问格中，1 个未产生问题，3 个提问后未获回答，另有 2 个虽已回答却跳过了应有的局部选择。漏归档 7，多余主任务提醒 5，重复主提醒 4，旁支宿主送达 12，其中规则臂贡献 8。交付报告另有五个超时或保持 active 的格子。一格可以同时出现多类错误。
- **计算与等待。** 客户端记录 618,579 token，代理记录 693,905 token，保留两种原始口径。已记录的最长送达约 323.2 秒，中位数约 154.4 秒。宿主观察、内部送达、面板呈现、用户点击及分析产物应各用自己的时间戳。
- **归档复验。** 发布证据在新目录重跑原评分与 162 项核验，并逐一核对 13 份分析的授权、来源与文件 SHA。本次复核新增模型调用为 0。原始现场运行来自 Linux，Windows 可见窗口的点击仍待实机验收。
- **程序回归。** Windows 上跟进系统测试 174 项通过、能力测试 73 项通过、实验类型检查通过。归档的三场景演示和四个 R7 反例也完成离线复跑。

已知三类失败值得恢复后优先调查。G2-W 的 V-C 在 B 先失败后首先超时，脚本记录 `answer.missing` 才重启，A 到达后才提全量分析问题。该格的原始时间线直接支持「重启前没有完成局部选择」。日志中另有关闭记忆编译的异常，因果链仍需复现。对照 T-C 在重启前成功选择 `wait_other`，重启后保持安静，直到 A 到达才询问。强规则有时先给出泛化问题并多发旁支提醒。文本摘要条件臂仍会把「过了／没过」「改口反过来」编译成反向条件。

## 恢复时先解决哪一件事

先跑 G2-W 两个对照：B 先失败时测首次局部问题是否在期限内可用，选择「等另一份」后再立即重启。用已知正确的承诺计划隔离模型差异，确认停机前后存在同一个等待项、相同任务版本及承诺引用。剩余报告到达时才提供一次可兑现的选择。保留原失败数据库作对照，完成后再用真实 Qwen 重跑 V-C 与 T-C。

这一步能区分承诺编译错误和生命周期错误。之后才值得扩展改口措辞、旁支提醒和长等待的比较。产品策略的采用应由新一轮的真实使用结果决定，优先观察用户收到的通知、授权范围以及实际分析是否有效。
